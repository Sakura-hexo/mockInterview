# AI 模拟面试平台 实现（步骤 6：复盘报告异步生成）

作者:开发执行 AI（ZCode）| 创建时间:2026-10-31

对应计划：`plans/2026-10-31/AI模拟面试平台-开发指令-步骤06.md`。

## 1 本批次做了什么

REPORT 意图从占位文案升级为完整异步报告流水线：MySQL 任务表驱动
（GENERATING、RUNNING、DONE、FAILED 状态机）、虚拟线程 Worker 两秒轮询、
分批评估逐题打分、二分恢复与显式降级、汇总四维评分、Markdown 输出。

新增文件：

- `session/ReportTask`（含四状态常量）、`ReportStore` 端口、`QaPair`
- `session/ReportGenerator`：配对（interviewer 为题、连续 user 拼为答、chat 跳过、
  自我介绍不计题）、首尾保留式压缩（答案 1200 字符、题目 800）、每批 8 对、
  批失败二分（全场 4 次额外调用预算）、降级项 0 分注明系统降级、汇总失败降级
  为均值并注明；tokenTotal 与时长取自存储层
- `session/ReportPrompts`（自写，AGPL 零拷贝）、`BatchEvaluation` 与
  `AggregatedReport` 结构化输出包装 record
- `session/ReportWorker`：单并发轮询、启动恢复残留 RUNNING、任务异常经 fail 记账
  不中断轮询；测试可注入短轮询间隔
- `session/ReportService`：五分支（题数不足、提交并结束会话、生成中、DONE 输出
  Markdown、FAILED 重置重试）
- `infra/MySqlReportStore`：submit 幂等（DONE 复用、FAILED 重置）、claim 条件更新、
  fail 三次置 FAILED 记原因
- `resources/sql/report-schema.sql`（t_report，session_id 唯一键）并入 init-db
- 测试：`FakeReportStore`、`ReportGeneratorTest`（7）、`ReportServiceTest`（6）、
  `ReportWorkerTest`（3）

改造文件：

- `SessionStore` 端口增 `readAll`（评估阶段全量读）、`endSession`、`durationMs`，
  MySqlSessionStore 与 PersistentSessionStore 同步实现
- `Supervisor`：REPORT 分支改调 ReportService 并注入；**不再追加用户消息**——
  报告评估读全量日志，复盘元命令不能污染问答配对（对步骤 5 行为的修订）
- `OrchestrationCliRunner`：接线 ReportWorker（try-with-resources 随进程停止）
  与 ReportService，主循环抽出 runLoop 方法，提示语加生成报告入口
- `SessionCliRunner`：增 `report show 会话id` 与 `report recover` 子命令
- `Prompts` 删除 REPORT_PLACEHOLDER；`SupervisorTest` 复盘测试拆为题数不足与
  提交任务两个，`LongSessionTest` 迁移五参构造

## 2 遇到的问题与解决方式

| 问题 | 解决方式 |
|---|---|
| 端口缺 readAll 编译失败（方法只在 MySqlSessionStore 上） | readAll 上移到 SessionStore 端口，两实现与 fake 同步补齐 |
| 二分测试计数口径错两次 | 调用器计数须含 StructuredOutputInvoker 内部 3 次重试：单批失败=3 次调用；断言改为 7（3+3+1）与 21（9+12+3）并注明推导 |
| init-db 文案漏 t_report | 补齐文案（表本身已由 schema 创建） |
| 想验证中断恢复没有现成手段 | 两阶段真机：阶段 1 提交后主动退出留 RUNNING；阶段 2 重启触发恢复 |

## 3 验证记录

单测：`mvn test` **69 个全绿**（步骤 5 的 52 加新增 17）。覆盖配对规则、分批
（20 题三批）、二分（半批成功半批降级、预算耗尽全降级不伪装）、汇总失败降级、
Worker claim 顺序与三振 FAILED、启动恢复、Service 五分支。

真机（s-24db9777，步骤 5 遗留 16 轮真实对话，compose mysql 3308）：

阶段 1——提交与异步性：

```text
会话已恢复：s-24db9777 | 已面试 16 轮
[意图 REPORT] 面试已结束，复盘报告生成中（任务 r-6ca9faaf）……
[意图 REPORT] 复盘报告仍在生成中，请稍后再输入「看报告」。
```

退出后 MySQL 核对：任务 RUNNING、t_session 状态 ENDED、ended_at 已写。

阶段 2——中断恢复与产出：重启后 Worker 打出
`启动恢复：1 个残留 RUNNING 任务已重置`（retry_count 保持 0，恢复不算失败），
重新生成约 50 秒后 DONE。对话内输入「看报告」输出完整 Markdown：16 题逐题
回顾、四维评分（总体 1、技术深度 2、表达 1、追问应对 1）、5 条改进建议、
总 token 102676、时长 1601000ms（均取自库内统计）。t_report 行 DONE、
report_json 2745 字符、error_msg 空。

低分是真实评估而非故障：验证脚本的回答大多与面试官实际提问错位（评测器
点评精确指出"回答 HashMap 却问分库分表"），唯一对题的 RocketMQ 题得了 4 分；
REPORT 轮本身 20 ms 零 token，异步设计生效。
