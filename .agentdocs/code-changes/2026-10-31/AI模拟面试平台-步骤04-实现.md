## 1 本批次做了什么

- `agent/AgentRuntime` 端口：generate（对话型，角色常量集中定义）与 modelName；interrupt 留步骤 7
- `infra/AgentScopeRuntime` 实现：agent 每轮重建以刷新系统提示词（已问题目清单会变），跨轮记忆由按 角色:会话 缓存的 stateStore 延续；面试官 maxIters 3 挂题库工具，chat maxIters 1 无工具，enableMetaTool(false)；角色分档模型留步骤 8
- `tool/QuestionBankAgentTool`：**直接实现 AgentTool 接口**（对指令中 @Tool 注解路线的替换——javap 核验 ToolCallParam.getInput/getToolUseBlock 后确认显式接口实现零反射风险，参数绑定与调用 id 完全可控），挂载到面试官 Toolkit
- `agent/Intent`、`agent/Router`（REPORT 关键词规则兜底优先不调模型，未命中走结构化分类，异常回退 INTERVIEW）
- `agent/InMemorySessionState`（内存版会话态：简历摘要、JD 要点、已问题目摘要、轮次；步骤 5 换持久化）
- `agent/Prompts`（四角色提示词集中：简历分析、闲聊、报告占位、面试官逐轮组装含防重复清单）
- `agent/Supervisor`：createSession（简历摘要经调用器、JD 经解析工具）、chat（三分流）；只依赖端口与调用器，零 AgentScope import（端口化红线达成）
- `agent/OrchestrationCliRunner`：交互式编排验证入口

## 2 遇到的问题与解决方式

| 问题 | 解决方式 |
|---|---|
| @Tool 注解反射的参数名绑定风险（指令已预警） | 核验 ToolCallParam 后改走 AgentTool 接口直接实现，参数与调用 id 显式可控 |
| agent 缓存与逐轮变化的系统提示词冲突 | agent 每轮重建、stateStore 按会话缓存共享——记忆与提示词更新兼得 |
| Git Bash 的 /tmp 路径传给 JVM 变成 \tmp 找不到文件 | 演示文件放 backend 目录用相对路径 |
| 编排 CLI 日志重定向后为 GBK 编码 | 验证时用 python 按 GBK 解码读取，代码无问题 |

## 3 验证记录

- `mvn -q test` 退出码 0：**39 个测试全绿**（步骤 3 的 28 个不回退 + 新增 11 个：Router 规则兜底不调模型、结构化分类、非法回退；Supervisor 建会话、面试注入断言（系统提示词含简历要点、岗位要点、工具说明、禁止重复条款）、多轮已问题目注入与会话延续、闲聊走 chat 角色、复盘占位不调智能体、会话不存在异常；QuestionBankAgentTool 元信息与调用 id 携带检索结果）——全部经 FakeAgentRuntime 与 fake 调用器，零真实模型
- 真机 10 轮编排（中转站模型加 Milvus 题库 61 题）：
  - 会话创建：简历摘要与 JD 要点准确提炼
  - 第 1 至 8 轮 INTERVIEW：面试官展现真实追问——线程池答后追问执行顺序与 IO 密集配置、HashMap 答后追问树化阈值 8 与退树化 6 及负载因子权衡、volatile 答后评价"只有一句话无法判断理解还是背诵"并下探一层、隔离级别答后指出"考点在后半段未提"（MVCC）；**题库工具真实调用**（回复中引用 QB-005、QB-006 题号）
  - 第 9 轮闲聊：意图 CHAT 分流正确，chat 角色轻量回应（6 秒，明显快于面试轮）
  - 第 10 轮「结束面试」：REPORT 规则兜底 0ms 返回占位话术，未调模型
  - 单轮耗时 17 至 35 秒（含路由分类、ReAct 多轮与工具检索），全程无崩溃
- 安全：`git grep "sk-"` 无结果；单文件均低于 100 行
