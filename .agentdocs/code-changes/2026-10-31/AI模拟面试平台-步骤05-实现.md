# AI 模拟面试平台 实现（步骤 5：会话持久化与上下文压缩）

作者:开发执行 AI（ZCode）| 创建时间:2026-10-31

对应计划：`plans/2026-10-31/AI模拟面试平台-开发指令-步骤05.md`。

## 1 本批次做了什么

核心改造：删除 AgentScope stateStore 自动累积记忆（token 线性膨胀的根源），改为
自组装上下文——常驻层系统提示词 + 用户输入层（前情摘要 + 最近 20 条窗口 +
8000 字符硬预算），窗口外消息攒 10 条触发一次 LLM 滚动合并摘要。
存储：MySQL 三表为事实源先写，Redis 热存可重建，进程重启 --resume 无损恢复。

新增文件：

- `session/SessionStore`（端口）、`StoredMessage`、`SessionSummary`、`SessionState`
  （自 InMemorySessionState 迁移，askedQuestions 降为 60 字×40 条）
- `session/ContextAssembler`：组装器（前情摘要 + 最近对话 + 本轮回答，字符硬预算，
  从最早丢弃、绝不丢当前回答）
- `session/ContextCompressor`：压缩器（攒批触发、滚动合并、失败降级不回退全量）
- `session/SessionCliRunner`：init-db 与 selfcheck 子命令
- `infra/MySqlDb`（Hikari 工厂 + ScriptUtils 建表）、`MySqlSessionStore`（JdbcTemplate）、
  `RedisSessionCache`（Lettuce 同步命令，TTL 24h 每轮续期）、`PersistentSessionStore`
  （组合实现：写先 MySQL 后 Redis，读 Redis 优先未命中回源重建）
- `resources/sql/session-schema.sql`：t_session / t_message / t_context_summary
- `agent/AgentReply`：回复 + token 用量 record
- 测试：`FakeSessionStore`、`ContextAssemblerTest`（6）、`ContextCompressorTest`（5）、
  `LongSessionTest`（2，含 50 轮模拟对话）

改造文件：

- `AgentRuntime` 端口：`Mono<String>` 改 `Mono<AgentReply>`，javadoc 改为无状态单次调用；
  `AgentScopeRuntime` 删 stores 缓存表、每次调用全新 agent、提取 ChatUsage token 用量
- `Supervisor`：注入 SessionStore 与 ContextCompressor，删内存 sessions 表，
  interviewTurn 按追加→组装→调用→落库→压缩时序重写，REPORT 分支也追加用户消息
- `Prompts.interviewerSystem` 改收 SessionState；`OrchestrationCliRunner` 增加 --resume
  与每轮 token 打印；`EnvKeys` 增 MYSQL_URL/USERNAME/PASSWORD（必填中文报错）/REDIS_URI；
  pom 显式声明 lettuce-core（版本走 Boot 管理 6.4.2）；`.env.example` 增会话持久化段；
  README 快速开始补会话层用法；删除 `agent/InMemorySessionState`

## 2 遇到的问题与解决方式

| 问题 | 解决方式 |
|---|---|
| SetArgs.ex 是实例方法非静态（编译错） | javap 核验后改 `new SetArgs().ex(TTL)` |
| 两处测试断言与设计不符 | 第 50 轮输入应含"问题49"（问题50 是本轮输出）；当前回答在【本轮回答】段不带"候选人："前缀 |
| 真机第 13 轮 `block(120s)` 超时中断 | 长会话后期单轮输出 2000+ token 实测 96-114 秒，Supervisor 与 AgentScopeRuntime 超时 120→300 秒、AgentLlmCaller 60→120 秒 |
| 中断反而成了真实 crash 场景 | 25 条消息已落库，--resume 续面验证崩溃恢复，轮次计数与上下文无缝衔接 |
| redis-cli 不在 PATH 无法手动清缓存 | 跳过（缓存丢失重建路径已由 selfcheck 的 evictCache 验证） |
| 共享工作区被前端会话切到 frontend 分支 | 沿用既定流程：本区提交后经临时 worktree cherry-pick 落 main |
| docker mysql 客户端中文显示 ???? | 客户端字符集显示问题，加 --default-character-set=utf8mb4 后确认存储为完好 UTF-8 |

与指令的两处偏差：DDL 列名 `round` 改 `round_no`（避开保留字风险）；
RedisSessionCache.close() 只调 client.shutdown()（显式 connection.close 会产生
"Connection is already closed" 告警）。

第 50 轮窗口含第 49 轮原文、第 1 轮原文已进摘要、token 逐条记录、换新实例无缝衔接。

schema），不再随轮数线性增长——旧实现 16 轮全量历史估算超 2.5 万 token。
