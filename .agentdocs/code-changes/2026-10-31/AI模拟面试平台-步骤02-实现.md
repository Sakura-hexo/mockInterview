## 1 本批次做了什么

按指令完成步骤 2 全部三段（2a 入库、2b 混合检索、2c 改写与分档）：

- `backend/pom.xml`：新增 `agentscope-extensions-rag-simple`（提供 EmbeddingModel 三路实现）与 `milvus-sdk-java:2.6.17`（直接编码其 v2 API）；exec 插件 mainClass 改为 `${exec.mainClass}` 属性引用，支持 `-Dexec.mainClass` 切换 CLI 入口
- `infra/EmbeddingModels`：与 ChatModels 同构的 embedding 工厂，复用 MODEL_PROVIDER 开关；维度随模型（text-embedding-v3 1024、nomic-embed-text 768）
- `infra/EnvKeys`：新增五个键（三路 embedding 模型名、MILVUS_URI、MILVUS_COLLECTION），均有代码默认值
- `rag/BankQuestion` 与 `rag/SearchHit`：record 载体
- `rag/QuestionBankParser`：题库 Markdown 解析，字段缺失即抛异常带题号
- `rag/MilvusQuestionStore`：Milvus 自封装混合检索存储——schema 含 search_text（中文 analyzer）经 BM25 函数服务端生成 sparse 稀疏向量，dense 稠密向量维度取自 embedding 模型；入库按题号查重幂等；hybridSearch 用 COSINE 加 BM25 双路 AnnSearch 经 RRFRanker(60) 融合；denseSearch 供对比
- `rag/RagCliRunner`：import（支持 --rebuild）与 search（支持 --topK、--dense-only、--no-rewrite）子命令
- `rag/QueryRewriter`：经 ChatModels 的查询改写器，每次调用独立会话，失败回退原查询；系统提示词含角色锁定声明
- `rag/SearchTiers`：长度分档（12 字符内 topK 3，否则 topK 5）与双查询融合（同题取高分）
- `backend/question-bank/java-backend.md`：种子 21 题，覆盖集合、并发、JVM、MySQL、Redis、网络、Spring 七方向
- 与指令的一处偏差：分档未设分数阈值——RRF 融合分是排名倒数之和，绝对阈值不可跨查询比较，阈值思路留待步骤 9 用命中率验证（SearchTiers 类注释有说明）

## 2 遇到的问题与解决方式

| 问题 | 解决方式 |
|---|---|
| CollectionSchema 与 Function 无公开构造器 | javap 核验后改用 `CollectionSchema.builder().build()` 与 `Function.builder()` 链式构造 |
| compose 起容器报容器名冲突 | 步骤 0 容器属 `ai-mock-interview` 项目（当年从仓库根目录起的）；旧容器均空数据（Milvus 未入库、MySQL 无表），删除旧项目容器与卷后按 README 约定的 `cd backend` 项目名重起，Milvus 三容器 healthy |
| `.env.example` 被误填真实配置（key 行粘了 URL） | 模板恢复为通用默认值；真实配置只留 backend/.env（不入库），模板文件头加了提示 |
| analyzerParams 的泛型 | `Map.<String, Object>of("type", "chinese")` 显式类型见证 |
| exec:java 的 mainClass 硬编码导致无法切换入口 | pom 属性化（见上） |
