# 性能与健壮性-实现

对应方案：`plans/2026-11-01/性能与健壮性-优化方案.md`。五步全部完成，单测与端到端验证通过。

## 变更内容（按方案步骤）

**步骤1 submit 撞键吸收**：`MySqlReportStore.submit` 的 INSERT 捕获 DataIntegrityViolationException 后回读已存在任务返回，并发双击结束不再 500。

**步骤2 状态机守卫**：SessionStore 端口新增 `casStatus(sessionId, from, to)`（MySQL 条件 UPDATE 判影响行数，Fake 同步实现）；`InterviewController.start` 改条件更新，双击第二个请求 409；`ChatStreamService` 新增会话级 in-flight 单飞守卫（chat 入口命中即 409）与 runTurn 状态复检（非 IN_PROGRESS 发 error 事件不追加消息）。

**步骤3 Worker 事务与清理**：ReportWorker 可注入 TransactionOperations，complete 与会话推进 REPORTED 两写同事务；AppConfig 注册 TransactionTemplate；删除 MilvusQuestionStore 上的无效 Transactional 注解；修正 MySqlSessionStore 头注释里过时的单写者假设表述。

**步骤4 压缩异步化**：Supervisor 注入维护执行器（缺省 Runnable 直接执行，兼容 CLI 与单测），compressIfNeeded 移出关键路径，SSE 的 metrics 与 done 不再等摘要；AppConfig 提供 ctx-compress 单守护线程（天然串行避免同会话摘要互相覆盖）。

**步骤5 预检索出题**：Supervisor 注入 QuestionBankTool，面试官每轮回复前按 JD 方向拼候选人回答前 120 字检索题库，候选题文本块注入系统提示词；题型判定从工具调用信号改为选题标记（出新题回复末尾单独一行「选题」，无编号——用户确认），后端 stripPickMark 落库前剥除、前端 onDelta 正则同步剥除；AgentScopeRuntime 卸载全部工具、角色统一 maxIters 1；QuestionBankAgentTool 及其测试删除；OrchestrationCliRunner 同步新装配。

**提交方式说明**：五步改动在 AppConfig、Supervisor 与测试文件上交叉，按方案原定「每步独立 commit」会让中间提交测试不绿，故合并为一次实现提交，步骤边界以本记录为准。

## 遗留与后续

- 出题轮剩余耗时为单次模型往返加中转站生成速度（约 15 到 25 token 每秒），进一步提速需换通道（DashScope 直连对比）或步骤 8 角色分级模型
