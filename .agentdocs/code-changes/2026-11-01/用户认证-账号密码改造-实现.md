# AI 模拟面试平台 用户认证 账号密码改造 实现

作者:Sakura（前端 AI）| 创建时间:2026-11-01

对应方案：`.agentdocs/plans/2026-11-01/用户认证-账号密码改造方案.md`。本次完成 A3（前端）与 A4（文档同步）；A1/A2（后端）待后端会话承接，交接指令见第五节。

## 一 决策落定（方案第 5 节，用户开工指令按推荐值执行）

开放注册、密码最短 8 位、存量清库、APP_TOKEN 退役、侧栏显示用户名。

## 二 前端改动清单（A3）

| 文件 | 改动 |
|---|---|
| `src/api/auth.ts` 新建 | login / register / logout 三方法 + `APP_USERNAME` 存取 |
| `src/pages/LoginPage.tsx` | 令牌单输入改为登录/注册页签 + 用户名密码双输入 + 文字型显示切换 + 客户端校验 + 401/409/400/429 错误文案 |
| `src/pages/LoginPage.css` | 新增页签、密码行、显示切换样式；主蓝只作用于 submit 按钮；去掉输入框等宽字体 |
| `src/components/Sidebar.tsx` | 退出改为先调 logout 接口再清本地凭据；底部"本机模式"改为显示当前用户名 |

`http.ts` 与 `App.tsx` 零改动：Bearer 机制与 RequireAuth 原样复用，与方案第 3 节预期一致。

## 三 验证记录

- 单元测试 19/19 通过；`npx tsc --noEmit` 零报错
- E2E（8081 临时 mock 按接口文档 4.0 契约搭建，vite 代理临时切换，验证后还原）：
  1. 登录页结构：页签、双输入框、显示切换、空表单禁用提交、新文案
  2. 注册密码过短客户端拦截"密码至少 8 位"
  3. 注册成功即登录进入 `/`，侧栏显示用户名，令牌写入 localStorage
  4. 退出：回 `/login`、本地凭据清空、服务端旧令牌请求变 401
  5. 密码错误提示"用户名或密码错误"
  6. 重复注册 409 提示"用户名已被占用，换一个试试"
  7. 显示/隐藏切换完整周期（password 与 text 互换、按钮文案联动）
  8. 正确登录进入 `/`
  9. 令牌损坏后刷新，listInterviews 401 → 全站跳 `/login` 并清令牌
- 429 限速文案为静态映射，E2E 未覆盖（mock 未实现限速），后端 A1 落地后联调复核

## 四 踩坑记录

- 同步 evaluate 里"切页签后立即 requestSubmit"会读到 React 旧渲染闭包的 mode，误走注册分支收到 409——测试脚本时序问题而非产品缺陷，真实用户两次点击之间必有渲染间隙
- IAB 出现两个同 URL 标签（导航失败的错误页 + 正常页）时按 URL 匹配会绑错，须按 DOM 特征（`.login-card` 存在性）区分
- vite dev server 进程跨会话会断，E2E 前需自查 5173 存活
