# 创建会话延迟-实现

作者:Sakura | 创建时间:2026-11-02 12:03（方案：`.agentdocs/plans/2026-11-01/创建会话延迟-优化方案.md`）

## 变更清单

A 调用合并 + B 结果缓存一次落地。

新增：

- `agent/SessionAnalyst.java` — 创建会话分析器：合并提示词一次产出摘要与岗位画像；
  不完整结果（digest 或 skills 缺失）不落缓存，重复建会话重试完整分析
- `session/AnalysisCache.java` — 缓存端口：keyOf 用两段文本各 strip 加竖线分隔符
  再取 SHA-256；NONE 空实现供 CLI 与单测
- `infra/MySqlAnalysisCache.java` — MySQL 实现：upsert 写入，并发双写无害
- `resources/sql/analysis-schema.sql` — t_analysis_cache 幂等建表，MySqlDb 随启动注册
- 测试：SessionAnalystTest 六用例、FakeAnalysisCache 假实现

改造：

- `Prompts.java` — RESUME_ANALYST_SYSTEM 替换为 CREATE_ANALYST_SYSTEM 四字段合并提示词
- `Supervisor.java` — createSession 改走 analyst.analyze 一次调用；
  构造器保留 5 参便捷版（内建无缓存分析器），Web 装配用 8 参注入
- `AppConfig.java` — analysisCache 与 sessionAnalyst bean，supervisor 接线
- `OrchestrationCliRunner.java` — CLI 也接 MySQL 缓存（重复建会话同样命中）
- 四个测试假调用器分支从"简历分析器"改为"创建分析器"合并 JSON；
  SupervisorTest 两处构造改 8 参

保留不动：JdParseTool 与其测试（ToolCliRunner 仍用）；开场白模板（start 不调模型）。
