### 3a 共享记录与结构化输出调用器

- `session` 包新增四个无框架依赖 record（架构方案 2.1 战术件，字段以接口文档第 3 节为准）：
  - `SessionConfig`（direction、difficulty、questionCount）
  - `ReportScore`（overall、technicalDepth、expression、followUpHandling，各 0 到 10）
  - `ReportItem`（question、userAnswerSummary、comment、score）
  - `InterviewReport`（sessionId、scores、items、suggestions、tokenTotal、durationMs）
- `infra/StructuredOutputInvoker`：统一 JSON 输出调用器（吸收自 interview-guide，全项目唯一入口，禁止业务代码各写各的解析）：
  - LLM 调用经注入的函数接口（入参 system 加 user 提示词，出参回复文本），生产实现走 ChatModels 的一次性会话（参照 rag/QueryRewriter 的做法，每次新 sessionId）；**单测注入 fake，不调真实模型**
  - 流程：渲染提示词与格式要求 → 调用 → 剥离 markdown 代码围栏 → gson 解析 → 失败则本地修复（围栏残留、尾逗号、字符串内未转义引号）→ 再失败带失败原因回填重试，上限 3 次 → 耗尽抛业务异常
  - 计数：调用数、重试数、失败数、累计耗时（AtomicLong 即可，步骤 8 换 Prometheus）

### 3b 五类工具（tool 包，统一注册与异常兜底）

- `ResumeParseTool`：纯文本直通；PDF（上限 5MB）经 Tika 提取原始文本；提取失败抛显式异常，不静默降级
- `JdParseTool`：jdText（上限 20KB）经 StructuredOutputInvoker 产出 `JdProfile` record（岗位方向、技能要求列表、加分项）；LLM 失败降级为以原文整体作为唯一要点，日志显式标注降级
- `QuestionBankTool`：包 `MilvusQuestionStore.hybridSearch` 与 `SearchTiers` 分档，输出给面试官用的题目文本块（题号、题干、标签）；步骤 4 再加注解适配挂到面试官
- `CompanyInfoTool`：P1 占位实现，固定返回「公司信息查询功能将在二期开放」，接口与注册先立住
- `ReportExportTool`：InterviewReport 转 Markdown 字符串（评分表、逐题回顾、建议三段）
- `Toolbox`：统一注册中心与调用入口——按名取工具、调用计时日志（工具名、耗时、成败）、异常兜底包装；app 侧只经 Toolbox 调工具
