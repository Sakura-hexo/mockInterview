# 会话列表索引-优化方案

作者:Sakura | 创建时间:2026-11-02 12:20

## 一、目标与边界

用户确认：把 `t_session.idx_session_user` 从单列 `(user_id)` 升级为联合索引
`(user_id, created_at)`，让"我的会话列表"这条最高频查询免 filesort。

边界：只动这一个索引；不加 t_report、t_message 的其它索引（评估见对话结论，
当前行数下均为负优化）。

## 二、现状与证据

列表查询 `WHERE user_id=? ORDER BY created_at DESC LIMIT ? OFFSET ?`
线上 EXPLAIN：`key=idx_session_user，Extra: Using filesort`——单列索引只管定位，
排序靠内存排序。联合后排序走索引倒序扫描，深分页不退化。

## 三、改动两点

1. 新装库：`sql/session-schema.sql` 的
   `KEY idx_session_user (user_id)` 改为 `KEY idx_session_user (user_id, created_at)`
2. 存量库：`SchemaMigrations` 新增幂等索引列集迁移 `ensureIndexColumns`——
   查 information_schema 按序取该索引列集，与目标不一致则 DROP 后 CREATE
   （MySQL 无 CREATE INDEX IF NOT EXISTS 也无改列语法）；
   替换原 `createIndex` 单列补建调用（新方法同时覆盖缺失与单列两种存量态）

## 四、验证方式

- `mvn test` 全绿
- 重启后端触发迁移后：`SHOW INDEX FROM t_session` 见 idx_session_user 两列；
  `EXPLAIN` 列表查询 Extra 无 filesort；列表接口回归正常

## 五、不做什么

- 不加 `t_report (status, created_at)`（4 行全扫更快，任务表规模化再议）
- 不加 `t_message (session_id, role, action)`（联合主键前缀已覆盖，写入放大零收益）
- 不动 t_user、t_analysis_cache（点查已最优）
