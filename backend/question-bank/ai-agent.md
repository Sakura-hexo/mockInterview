# AI 与 Agent 题库（第一批）

## AG-001
题干：说说什么是 Agent？它和普通聊天大模型有什么区别？
要点：Agent 是能自主拆步骤、用工具、试错完成目标的 AI 程序；核心四要素为 LLM 大脑、感知输入、行动工具与记忆；公式化表达 Agent 等于 LLM 加记忆加规划加工具调用；区别于问答式聊天模型，它给目标即可自己推进
标签：Agent,基础概念
来源：小假八股引用

## AG-002
题干：一个 Agent 系统的基础框架是什么？
要点：本质是感知-决策-执行的闭环循环；四大模块：大模型大脑负责推理决策（典型 ReAct 模式）、感知模块接收多模态输入、工具模块执行外部动作、记忆模块分短期上下文与长期向量库两层
标签：Agent,架构
来源：小假八股引用

## AG-003
题干：Workflow、Agent、Tools 三者是什么关系？
要点：Workflow 是写死的固定流程，Agent 是自主决策体，Tools 是模型可调用的外部能力；Workflow 适合明确重复任务，Agent 适合开放不确定任务；Agent 能根据当前状态决定下一步，而 Workflow 每步都预先定好
标签：Agent,基础概念
来源：小假八股引用

## AG-004
题干：Agent 的记忆压缩通常有哪些方法？
要点：五种主流方法：摘要式压缩（可分层金字塔式）、滑动窗口加重要度评分、向量检索式压缩存储、专用压缩模型生成记忆 token、结构化三元组存图数据库；实际落地通常混合使用，且要定期重写过时记忆
标签：Agent,记忆管理
来源：小假八股引用

## AG-005
题干：LLM、RAG、Agent 三者之间有什么区别与联系？
要点：LLM 是底座负责生成推理但知识会过时且有幻觉；RAG 是先检索再生成的增强方式解决知识不新；Agent 是自主决策加工具调用的应用框架解决只会聊天不会干活；Agent 可把 RAG 当作自己的一个工具，三者不是互斥关系
标签：Agent,RAG,基础概念
来源：小假八股引用

## AG-006
题干：Agent 的推理模式有哪些？ReAct 和 CoT、ToT 有什么区别？
要点：三类：纯推理型（CoT、ToT 只在模型内部推导）、行动型（ReAct 思考行动观察循环）、高级型（Reflexion 自我反思、Plan-and-Solve）；CoT 适合逻辑推导但是静态不可纠错，ToT 分叉探索适合难题但成本高，ReAct 与外部环境强交互适合真实工具任务；ReAct 的坑是延迟高且易死循环，生产要加最大轮次限制
标签：Agent,ReAct
来源：小假八股引用

## AG-007
题干：如何解决大模型在 Agent 任务中的幻觉和失控问题？
要点：三层治理：一限制自由度，用状态机拆成固定步骤、系统提示词写死规则；二外部矫正，事实类强制走 API 或 RAG 检索、加独立验证层驳回矛盾；三安全围栏，权限最小化、熔断机制（最大轮次超时报错阈值）、沙箱执行，最后加反思节点自动评估
标签：Agent,可靠性
来源：小假八股引用

## AG-008
题干：Agent 的记忆是如何设计的？短期记忆和长期记忆有什么区别？
要点：短期记忆即上下文窗口，存当前对话与中间结果，会话级且容量有限；长期记忆持久化到向量库，Embedding 后按语义检索回填上下文；区别在生命周期、存取机制（顺序截断 vs 检索式）与容量成本；进阶点是记忆固化——高频短期记忆写入长期记忆，注意不要盲目塞满上下文稀释注意力
标签：Agent,记忆管理
来源：小假八股引用

## AG-009
题干：Agent 的 Planning 有哪些常见方式？
要点：三类递进：无反馈一次性规划（CoT、Plan-and-Solve）简单快但不检查结果；有反馈规划（ReAct 边做边看、Reflexion 失败后生成口头反馈存记忆避免重蹈）鲁棒适合交互任务；内生推理规划（ToT、GoT 每步多候选取胜可回溯）适合超高难度但贵且慢
标签：Agent,规划
来源：小假八股引用

## AG-010
题干：如何避免 Agent 陷入死循环？
要点：四个层面：提示词里写刹车逻辑（同工具同结果两次或三步无进展必须停下）；工程硬熔断（最大调用次数与总超时强制终止）；全链路日志观测定位循环模式；状态记忆让每步把已试过的方法写进上下文避免重蹈
标签：Agent,可靠性
来源：小假八股引用

## AG-011
题干：多个工具同时可用时，Agent 如何选择调用哪个？
要点：五个决策依据：任务与工具的语义匹配度；工具历史表现与信任度；成本与效率优先性价比高者；任务依赖关系决定串行顺序；不确定时可先调轻量工具试探。高级做法是根据历史经验动态排序
标签：Agent,工具调用
来源：小假八股引用

## AG-012
题干：工具调用失败时（超时、异常、返回格式错误），系统如何保证可靠性？
要点：超时加重试且必须指数退避防止打爆下游；连续失败触发熔断走兜底话术而非卡死；返回先做格式校验，格式错误按失败处理；所有失败记录详细日志带参数便于复盘；对外给友好兜底响应
标签：Agent,工具调用,可靠性
来源：小假八股引用

## AG-013
题干：长对话场景下，如何管理超长的对话历史？
要点：选择性遗忘只存关键信息丢弃客套话；滑动窗口加滚动摘要组合，最近几轮完整保留更早的压缩成摘要；客服类场景用向量检索只召回相关历史片段，强记忆场景维护结构化用户画像；超过阈值触发长程总结作为新记忆起点
标签：Agent,上下文管理
来源：小假八股引用

## AG-014
题干：多个用户同时请求 Agent 服务，如何保证 LLM 调用的稳定性？
要点：限流排队（令牌桶或消息队列）防瞬时冲击；超时加指数退避重试加断路器熔断防抖动雪崩；Token 配额与业务隔离防止单用户拖垮全局；相同问题加 Redis 结果缓存省费用提响应。核心口径：限流防冲击、重试防抖动、隔离防影响、缓存防重复计算
标签：Agent,高并发
来源：小假八股引用

## AG-015
题干：Agent 推理耗时长，如何设计异步响应架构？
要点：三步：请求进来立即返回任务 ID 释放连接；真正推理进消息队列由 Worker 消费，天然解耦；结果落库关联任务 ID，前端轮询或 WebSocket、SSE 推送拿结果；配套超长任务的 TTL 与 pending、processing、completed、failed 状态机
标签：Agent,异步架构
来源：小假八股引用

## AG-016
题干：Agent 行为难以预测，如何做调试和追踪？
要点：先白盒化——密集记录每次 LLM 的输入输出、工具参数与返回、token 与耗时，强制输出结构化思考链；再可控复现——固定 temperature 与 seed，工具调用录成 mock 跑回归；最后分层排查——外层看轨迹哪步错、中层单测该步提示词、底层查工具返回质量
标签：Agent,可观测性
来源：小假八股引用

## AG-017
题干：如何评估一个 Agent 系统的效果？
要点：三层指标：底线看任务完成率与最终结果对不对；过程质量看步数 token 成本、工具选择准确率、轨迹合理性（防蒙对）；再加成本与鲁棒性（换说法重问、自洽性多次采样）；方法上自动化评估与人工抽检结合，覆盖对抗测试与失败 case 持续迭代
标签：Agent,评估
来源：小假八股引用

## AG-018
题干：如何保证 Agent 系统的可靠性？
要点：三层：约束自由发挥——结构化输出强制 JSON、任务拆步骤逐步校验格式；工具加护栏——SQL 语法校验限行数、API 超时重试、危险操作人工确认或沙箱；失败可观测可回滚——链路追踪加幂等设计加检查点断点续跑；配套回归测试集覆盖 Bad Case
标签：Agent,可靠性

## RG-001
题干：说说什么是 RAG？它解决什么问题？
要点：先查资料再回答：用户提问先去知识库检索相关片段，与问题一起拼进提示词再让模型生成；解决模型知识过时与幻觉两大问题；答案有据可循可追溯；与微调的区别是 RAG 像开卷考试成本低可动态更新，微调像内化学习成本高适合改变风格
标签：RAG,基础概念
来源：小假八股引用

## RG-002
题干：RAG 系统的完整处理流程是什么？
要点：离线索引阶段：文档切块、Embedding 向量化、向量与原文一起入向量库；在线检索阶段：问题用同一模型向量化、相似度搜索取 Top-K 片段；在线生成阶段：问题加片段拼提示词交给模型生成，要求不瞎编、信息冲突能判断可信度、缺失敢说无法回答；输出可附原文片段与追问建议
标签：RAG,流程
来源：小假八股引用

## RG-003
题干：RAG 是怎么存文档的？常见的文档切割策略有哪些？
要点：存的是向量加原文块；六种切割策略由简到繁：固定长度（加 overlap 防语义断裂）、按句子、按段落、递归字符切割（段落大于句子大于词的优先级）、语义切割（相邻句向量相似度陡降处切）、格式感知切割（代码按函数类、Markdown 按标题层级）
标签：RAG,分块策略
来源：小假八股引用

## RG-004
题干：常用的向量检索算法有哪些？
要点：本质是精度换效率；三大流派：基于树（KD-Tree 高维灾难已少用）、基于量化（IVF 聚类分桶粗筛，PQ 乘积量化压缩省内存适合亿级数据）、基于图（HNSW 多层近邻图类似跳表，查询快召回高但内存大构建慢，当前最主流）
标签：RAG,向量检索
来源：小假八股引用

## RG-005
题干：向量检索流程中 Embedding 和 Rerank 各自的作用是什么？
要点：Embedding 负责快而粗的召回，把语义转成向量但单向量表达整段会丢细节；Rerank 用 cross-encoder 把 query 与每个候选拼对精打细算，能理解否定对比多跳关系但计算量大；工业标准做法：Embedding 召回一百条，Rerank 精排出十条
标签：RAG,向量检索
来源：小假八股引用

## RG-006
题干：向量检索引擎算法 IVF 和 HNSW 的核心区别是什么？
要点：IVF 先聚类分桶再就近桶内找，像先猜后确认，构建快内存小但边界点易漏；HNSW 分层图从顶层大步逼近逐层细化，像跳表跳着走，精度高速度稳但建图慢内存大；选型口径：上亿且资源有限选 IVF 加 PQ，百万到千万级要求高召回选 HNSW，但 HNSW 删除更新难维护成本高
标签：RAG,向量检索
来源：小假八股引用

## RG-007
题干：什么是向量数据库？该如何选型？
要点：传统数据库存精确值靠匹配筛选，向量库存 Embedding 坐标解决找相似的问题；选型：小团队起步用云服务（Pinecone、Zilliz Cloud）别自己搭集群；大体量高并发上 Milvus 或 Weaviate；小体量省钱本地玩用 Chroma 或 LanceDB 零运维
标签：RAG,向量数据库
来源：小假八股引用

## RG-008
题干：意图定向检索和全局向量检索的区别是什么？
要点：全局向量检索对整个知识库做语义匹配，能发现隐含语义但范围广易召回噪声且大库扫描慢；意图定向先识别问题意图与主题，再缩小到分类子集里检索，精度高速度快但强依赖意图识别的准确率，识别错则全错
标签：RAG,检索策略
来源：小假八股引用

## RG-009
题干：向量检索和关键词检索的区别是什么？实际怎么结合？
要点：关键词是字面精确匹配可解释强但漏同义；向量是语义匹配容错强能理解意思但计算贵且黑盒；结合方式：精确筛选（型号、编号、法律条款）走关键词，模糊语义走向量；主流是混合检索，向量召回一批再用关键词或重排精排
标签：RAG,检索策略
来源：小假八股引用

## RG-010
题干：什么是多路召回？
要点：单一召回策略覆盖不全（协同过滤冷启动、热门缺乏个性化），工业界多通道并行召回：协同过滤、热度、向量双塔、倒排关键词、地理等各取几百上千候选，合并去重送排序层；好处是覆盖率与多样性提升，单路失效不致全盘崩溃，工程易扩展
标签：RAG,检索策略
来源：小假八股引用

## RG-011
题干：RAG 的检索优化策略有哪些？
要点：三大方向：索引优化（语义分块、元数据增强支持先过滤、向量加 BM25 混合索引防漏关键词）；查询优化（查询改写、HyDE 用假设答案去检索、多查询生成融合去重）；重排序（cross-encoder 对 query 与 chunk 对打分，加几十毫秒换显著准确率）
标签：RAG,检索优化
来源：小假八股引用

## RG-012
题干：如何避免 RAG 系统中大模型的幻觉？
要点：源头提升检索质量：混合检索加 rerank 加相关性阈值，宁缺勿滥；提示词约束：只基于文档回答、没有就说找不到、逐条引用来源；加事实核查：另一模型或规则校验答案实体是否在原文；体验兜底：高亮引用片段、置信度打分、数字日期后处理比对原文
标签：RAG,幻觉治理
来源：小假八股引用

## RG-013
题干：如何量化评估 RAG 系统的效果？
要点：检索侧看命中率与 MRR（Top5 命中率通常要 90% 以上）；生成侧用忠实度（是否胡说）与答案相关性，可用 RAGAS 框架自动打分；人工抽检百个 case 分级标注，高风险场景人工通过率要 95% 以上才上线；再加业务指标如追问率与解决率，分数与用户满意要互相印证
标签：RAG,评估
来源：小假八股引用

## RG-014
题干：两份知识库对同一个模糊问题给出不同答案，系统如何处理冲突？
要点：录入阶段防呆：冲突检测模块发现相似但矛盾的切片打冲突标签进人工审核，按来源优先级（官方文档大于 FAQ 大于博客）取舍或双保留加争议标注；检索阶段让步：两个答案都召回并在上下文注明观点不一致，提示模型向用户分别陈述或反问场景；高频场景做用户反馈闭环反向清洗知识库
标签：RAG,数据治理
来源：小假八股引用

## RG-015
题干：RAG 检索召回率过低时，应如何排查和优化？
要点：先排查四项：切分是否过大过小或切断关键信息、query 是否口语化短且多指代、embedding 模型与领域是否匹配、TopK 与阈值是否卡太紧；再针对性优化：query 改写与多角度扩写、语义分块加重叠或父子索引、微调或换领域 embedding、混合检索加 rerank；习惯顺序是先查切分和 query 再动检索方式最后才换模型
标签：RAG,调优
来源：小假八股引用

## RG-016
题干：如何评估 RAG 的输出来自知识库证据而不是模型幻觉？
要点：三道锁：强制引用格式，答案必须附引用的原文段落，系统提示词写死没有就拒答；独立溯源打分，生成后再用小模型或规则算答案关键事实与原文片段的相似度，低于阈值判幻觉重新生成或拒答；前端证据展示，原文高亮可点击，用户亲验证据
标签：RAG,幻觉治理
来源：小假八股引用

## LM-001
题干：说说什么是 Function Calling？
要点：解决模型无法获取实时信息与无法执行动作的短板；流程：预定义函数描述与参数告知模型、模型判断后返回结构化调用指令、程序执行真实 API、结果回传模型组织成自然语言；本质是大模型与外部世界的桥梁
标签：LLM应用,工具调用
来源：小假八股引用

## LM-002
题干：说说什么是 MCP？
要点：AI 大模型的通用 USB 接口；定义应用与工具服务器之间的标准通信协议，让文件、数据库、各类工具即插即用，免去每个工具单独写插件的重复开发；换前端应用不需要改工具代码，定位是 AI 生态的基础设施
标签：LLM应用,MCP
来源：小假八股引用

## LM-003
题干：说说什么是 Skill？
要点：能解决特定问题、可复用的能力模块，是知道加能做到；强调场景化与组合性：封装提示词、流程与脚本，拿出来就能用可跨系统复用；不只是知识而是稳定产出结果的能力，AgentScope 等框架中对应打包好的技能单元
标签：LLM应用,Skill
来源：小假八股引用

## LM-004
题干：MCP、Skill、CLI 三者有什么区别？
要点：三层能力栈：Skill 是岗位说明书加工具包，固化流程与经验让 AI 按标准做；MCP 是万能插头，标准化协议解决 AI 怎么安全连接外部系统，适合企业级统一管理与审计；CLI 是直接上手干活的命令行，Token 消耗最低适合高频固定操作；日常组合是 Skill 定流程加 CLI 执行，企业复杂场景上 MCP
标签：LLM应用,MCP,Skill
来源：小假八股引用

## LM-005
题干：MCP 协议和 Function Calling 有什么区别？
要点：Function Calling 是模型厂商 API 层的调工具能力，只管模型决定调什么，工具注册解析各自硬编码；MCP 是开放协议管工具接入标准，客户端自动发现工具即插即用，应用与工具解耦；两者不冲突：MCP Server 内部实现往往就用 Function Calling 触发，协议层标准化与执行层能力是互补关系
标签：LLM应用,MCP,工具调用
来源：小假八股引用

## LM-006
题干：WebSocket 和 SSE 有什么区别？
要点：WebSocket 双向全双工需升级 ws 协议；SSE 单向服务器推走普通 HTTP 长连接，兼容性与自动重连更好；SSE 适合推送类场景实现简单，WebSocket 适合真正双向实时交互如聊天游戏；SSE 主要是文本，WebSocket 支持二进制；只需服务器推优先 SSE 成本低
标签：LLM应用,通信协议
来源：小假八股引用
