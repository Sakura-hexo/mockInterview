# Java 后端题库（种子批次）

来源标记说明：个人笔记、AI生成、开源引用（须署名）。本批次为 AI 生成种子，待人工校对后扩充至 300 题。

## QB-001
题干：HashMap 在 Java 8 之后的底层结构是怎样的？
要点：数组加链表加红黑树；链表长度超过 8 且数组长度达到 64 才树化；负载因子 0.75，扩容翻倍并重新分布节点
标签：Java集合,HashMap
来源：AI生成

## QB-002
题干：ConcurrentHashMap 在 Java 8 中是如何保证线程安全的？
要点：放弃分段锁，改用 CAS 加 synchronized 锁单个桶头节点；扩容协助转移；size 统计用 CounterCell 分散热点
标签：Java集合,并发,ConcurrentHashMap
来源：AI生成

## QB-003
题干：ArrayList 和 LinkedList 的区别与选型？
要点：动态数组随机访问 O(1) 尾插均摊 O(1)，扩容 1.5 倍；双向链表头尾插删 O(1) 随机访问 O(n)；绝大多数场景选 ArrayList
标签：Java集合,ArrayList
来源：AI生成

## QB-004
题干：什么是 fail-fast？如何避免遍历时修改集合的异常？
要点：迭代器对比 modCount 与 expectedModCount，不一致抛 ConcurrentModificationException；遍历中修改须用 Iterator.remove 或并发集合
标签：Java集合,fail-fast
来源：AI生成

## QB-005
题干：synchronized 和 ReentrantLock 的区别？
要点：前者 JVM 层监视器锁自动释放；后者 API 层锁，支持公平锁、可中断、超时获取与多个 Condition；简单互斥用前者，高级特性用后者
标签：并发,锁
来源：AI生成

## QB-006
题干：volatile 关键字的作用是什么？能保证原子性吗？
要点：保证可见性与禁止指令重排（内存屏障）；不保证复合操作原子性，典型场景是一写多读的状态标志位与双检锁配合
标签：并发,JMM
来源：AI生成

## QB-007
题干：线程池有哪些核心参数？任务提交后的执行顺序是怎样的？
要点：corePoolSize、maximumPoolSize、keepAliveTime、workQueue、threadFactory、handler；核心线程满进队列，队列满开非核心线程，到上限触发拒绝策略
标签：并发,线程池
来源：AI生成

## QB-008
题干：ThreadLocal 为什么可能内存泄漏？
要点：ThreadLocalMap 的 key 是弱引用，GC 后 key 为 null 但 value 仍被线程持有；线程池线程复用放大泄漏；用完必须 remove
标签：并发,ThreadLocal
来源：AI生成

标签：JVM,内存区域
来源：AI生成

## QB-011
题干：类加载器的双亲委派模型是什么？哪些场景会打破它？
要点：子加载器先委托父加载器，保证核心类唯一与安全；打破场景有 SPI 的线程上下文加载器、热部署、OSGi 模块化
标签：JVM,类加载
来源：AI生成

## QB-012
题干：MySQL 为什么用 B+ 树做索引而不用 B 树或哈希表？
要点：B+ 树非叶子节点只存键，扇出更大树更矮，磁盘 IO 更少；叶子节点链表利于范围查询；哈希不支持范围与排序
标签：MySQL,索引
来源：AI生成

## QB-013
题干：哪些写法会导致索引失效？
要点：不满足最左前缀；索引列上用函数或运算；隐式类型转换（字符串列用数字查）；like 前导百分号；or 连接了非索引列
标签：MySQL,索引
来源：AI生成

## QB-014

标签：MySQL,事务,MVCC
来源：AI生成

标签：MySQL,调优
来源：AI生成

## QB-016
题干：Redis 的 RDB 和 AOF 持久化有什么区别？
要点：RDB 定期全量快照，文件小恢复快，可能丢最后一次快照后的数据；AOF 追加写命令，可每秒刷盘更安全但文件大恢复慢；4.0 后混合持久化
标签：Redis,持久化
来源：AI生成

## QB-017
题干：缓存穿透、击穿、雪崩分别怎么应对？
要点：穿透查不存在的数据，用布隆过滤器或空值缓存；击穿热点 key 过期，用互斥锁或逻辑过期；雪崩大量 key 同时失效，用随机 TTL 与多级缓存
标签：Redis,缓存设计
来源：AI生成

## QB-018
题干：缓存与数据库的双写一致性怎么保证？
要点：常用 Cache Aside 读缓存 miss 回源；写库后删缓存；延迟双删缓解主从延迟；强一致要求高时用订阅 binlog 的异步更新
标签：Redis,一致性
来源：AI生成

## QB-019
题干：TCP 为什么是三次握手和四次挥手？
要点：三次确认双方收发能力并同步初始序列号，两次无法防历史连接；挥手多一次因被动方半关闭还要发剩余数据；TIME_WAIT 等 2MSL 确保对方收到确认
标签：网络,TCP
来源：AI生成

标签：网络,HTTPS
来源：AI生成
