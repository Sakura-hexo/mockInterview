## JB-001
题干：说一下什么是面向对象？
要点：面向对象用类与对象把现实事物建模为代码，核心是封装、继承、多态三大特性：封装把数据与操作绑定、只暴露有限接口，内部数据更安全；继承让子类复用父类通用特征并扩展特有功能，减少重复代码；多态使同一指令作用于不同对象产生不同行为，设计时无需关注具体类型，代码更通用易扩展。目的是让代码结构清晰、贴近思考方式，便于构建与维护复杂项目。
标签：Java,基础概念
来源：付费笔记

## JB-004
题干：说一下 Java 中重载和重写的区别
要点：重载是同一个类中方法名相同、参数列表不同，编译期即可确定调用版本；重写是子类覆盖父类方法，运行期根据实际对象类型决定调用，二者都体现多态。静态方法可以被重载；但不能被重写，因为静态方法属于类而非对象，子类定义同名同参静态方法只是隐藏父类方法，不构成重写。
标签：Java,面向对象
来源：付费笔记

## JB-005
题干：说一下 Java 中的深拷贝、浅拷贝、引用拷贝
要点：引用拷贝仅新增指向原对象的引用，实为同一对象，修改互相影响；浅拷贝创建新对象，但引用型成员变量仍与原对象共享，通过实现 Cloneable 接口、重写 clone() 调 super.clone() 实现；深拷贝创建新对象并递归复制所有引用类型成员，新旧对象完全独立无共享，可手动递归 clone() 或经序列化反序列化完成。
标签：Java,对象拷贝
来源：付费笔记

## JB-006
题干：你知道有哪些线程安全的集合？
要点：常用有 ConcurrentHashMap、CopyOnWriteArrayList、CopyOnWriteArraySet、早期方法级加 synchronized 的 Vector 与 Hashtable（已不推荐）、Collections 工具类包装的同步集合。按原理分三类：写时复制型，写操作复制整个底层数组，适合读多写少；分段锁与 CAS 型，ConcurrentHashMap JDK7 用分段锁、JDK8 改用 synchronized 加 CAS，锁粒度更细并发度更高；包装型，各方法加同步锁，性能差。选型按读写场景定，并留意复合操作的线程安全。
标签：Java,集合
来源：付费笔记

## JB-007
题干：说一下 Java 中 == 与 equals() 的区别
要点：== 对基本类型比值，对引用类型比内存地址，即判断两个引用是否指向堆中同一对象。equals() 是 Object 的方法，默认实现就是 ==，未重写时与 == 等价；String、Integer、Date 等核心类已重写 equals()，改为比较对象内容是否逻辑相等。实际开发比较内容（如校验用户名密码）几乎都用 equals()，== 仅用于枚举比较或需检查引用唯一性的场景。
标签：Java,基础概念
来源：付费笔记

## JB-008
题干：说一下 hashCode() 和 equals() 的区别，为什么重写 equals() 就要重写 hashCode()？
要点：职责不同：equals() 判断两对象逻辑上是否相等；hashCode() 快速计算哈希码，支撑 HashMap、HashSet 等哈希集合高效工作。Java 约定：equals() 相等则 hashCode() 必须相等；hashCode() 相等则 equals() 不一定相等。若只重写 equals() 不重写 hashCode()，逻辑相等的对象哈希值不同，会被放入不同桶，导致 get 取不到刚 put 的值。
标签：Java,基础概念
来源：付费笔记

## JB-009
题干：说一下 Java 基本数据类型和引用类型
要点：基本类型八种分四类：整型 byte、short、int、long，浮点型 float、double，字符型 char，布尔型 boolean，变量直接存值于栈；引用类型含类、接口、数组三类，变量存的是堆中对象地址。核心区别三点：存储上基本类型存值在栈、引用类型存地址、对象在堆；赋值上基本类型拷贝值互不影响，引用类型拷贝地址、两引用共享同一对象；默认值上基本类型各有默认（如 int 为 0），引用类型均为 null。
标签：Java,基础概念
来源：付费笔记

## JB-010
题干：说一下 final 关键字
要点：final 表示最终的、不可更改，作用随修饰目标分三类：修饰变量最常见，基本类型变量值不可再变，引用类型变量引用地址不可变但对象内容可改；修饰方法则该方法不能被子类重写；修饰类最严格，该类不允许被继承，如 JDK 中的 String 类。
标签：Java,关键字
来源：付费笔记

## JB-011
题干：说一下 Java 自动装箱与拆箱是什么？
要点：自动装箱与拆箱是 Java 5 引入的语法糖，用于简化基本类型与对应包装类之间的转换。自动装箱：把基本类型直接赋给包装类引用时，编译器自动调用 valueOf() 包装；自动拆箱：在需要基本类型值的地方使用包装类对象时，编译器自动调用 xxxValue() 取出内部值。
标签：Java,基础概念
来源：付费笔记

## JB-012
题干：说一下 String，StringBuilder，StringBuffer 的区别及使用场景
要点：可变性：String 不可变，拼接实际创建新对象，频繁修改产生大量临时对象；StringBuilder 与 StringBuffer 基于可变字符数组，在原对象上操作。线程安全：String 不可变天然线程安全；StringBuffer 关键方法加 synchronized，安全但有开销；StringBuilder 无锁线程不安全、性能最高，一般性能排序 StringBuilder 大于 StringBuffer 大于 String。场景：常量、配置、HashMap 的 key 用 String；单线程频繁拼接（循环拼 SQL、组装 JSON）用 StringBuilder；多线程共享修改同一字符串才用 StringBuffer。
标签：Java,字符串
来源：付费笔记

## JB-013
题干：说一下什么是泛型及应用
要点：泛型即类型参数化，类型本身成为参数、调用时才确定具体类型，如 List 的 T。既保证类型安全、避免运行时类型错误，又提高代码复用性。应用：集合类最常用；泛型集合直接存值、避免装箱拆箱效率更高；泛型方法一套逻辑支持多种类型、免多次重载；泛型接口让比较等逻辑类型安全；还可通过约束限制类型参数（如必须为类、必须实现某接口）。
标签：Java,泛型
来源：付费笔记

## JB-014
题干：说一下 Java 的 String 的底层实现
要点：String 底层是字符数组，Java 9 前为 char 数组，Java 9 起改为 byte 数组加编码标志位：Latin-1 字符单字节存储，中文等 Unicode 字符按 UTF-16 用两或四字节，更省内存。String 不可变，拼接、替换等操作实际都创建新对象。不可变的好处：作为 HashMap 的 key 不怕被改动、天然线程安全、支持字符串常量池复用相同字面量并便于哈希缓存，核心是为安全性与性能设计。
标签：Java,字符串
来源：付费笔记

## JB-015
题干：说一下 Java 里面有哪些锁？
要点：按实现分：synchronized 是 JVM 级非公平可重入互斥锁，获取失败即阻塞；ReentrantLock 为显式可重入锁，支持公平锁、可中断 lockInterruptibly、超时 tryLock、多 Condition；ReentrantReadWriteLock 共享读、独占写、读写互斥，适合读多写少；乐观锁基于 CAS 与原子类（AtomicInteger 等），无阻塞但高竞争重试 CPU 开销大；JDK 1.6 起 synchronized 有锁膨胀，无锁、偏向锁、轻量级锁、重量级锁逐级升级。按理念分：公平与非公平、独占与共享、可重入与否。选型优先 synchronized，需高级功能才用 ReentrantLock。
标签：Java,锁,并发
来源：付费笔记

## JB-016
题干：说一下 Java 中的反射机制
要点：反射允许程序在运行时动态获取类信息并操作其属性、方法和构造器，包括访问 private 字段、动态调用任意方法、通过 Class 对象实例化类而非 new。框架应用：Spring IOC 读配置类名反射创建 Bean；JDBC 用 Class.forName() 加载驱动；Jackson、Fastjson 依类结构反射完成 JSON 与对象互转。底层为类编译成字节码后，Class.forName() 或 getClass() 时 JVM 在方法区（元空间）加载并创建 Class 对象，反射获取的信息均来自该对象。
标签：Java,反射
来源：付费笔记

## JB-017
题干：uncheckedException 和 checkedException 区别？
要点：受检异常编译期被检查，必须 try-catch 或 throws 声明否则编译报错，典型如 IOException、SQLException；非受检异常编译器不检查、运行时才暴露，典型如空指针、数组越界。继承上受检异常直接继承 Exception，非受检异常是 RuntimeException 的子类。理念上受检异常代表可预期、可恢复的业务异常，强制调用方处理；非受检异常代表程序缺陷，捕获也难恢复。滥用受检异常会使 try-catch 臃肿，Spring 等框架倾向将其包装为非受检异常。
标签：Java,异常
来源：付费笔记

## JV-004
题干：说一下 CMS 收集器的工作流程及缺点
要点：CMS 是面向老年代、以最短停顿为目标的并发收集器，核心是并发标记-清除，流程四步：初始标记，STW，仅标记 GC Roots 直接关联的老年代对象；并发标记，与用户线程并发、耗时最长但不停顿；重新标记，STW 修正并发期间变动；并发清除，不停顿。以两次短 STW 换取最耗时阶段并发执行。缺点：并发阶段占用 CPU 致吞吐下降；无法处理浮动垃圾，需预留空间，预留不足触发 Concurrent Mode Failure、退化为 Serial Old 长停顿；标记-清除产生内存碎片，分配大对象可能提前 Full GC。JDK 9 废弃、JDK 14 移除。
标签：JVM,垃圾回收,CMS
来源：付费笔记

## JV-005
题干：说一下 G1 收集器的工作流程与缺点
要点：G1 是 JDK 9 默认收集器，目标为可控停顿下尽量高吞吐，将堆划分为大小相等的 Region、不再要求分代物理连续。平时 Young GC 回收 Eden Region，存活对象进 Survivor 或晋升 Old；关键期走并发标记周期：初始标记、并发标记、最终标记（SATB 修正）、筛选回收，按停顿目标评估各 Region 回收价值后混合收集，分批回收年轻代与部分老年代 Region。缺点：记忆集、卡表等结构带来额外内存与 CPU 开销；默认约 2048 个 Region，小内存应用不友好；回收赶不上分配会退化 Serial Old Full GC；碎片改善但未根除。适合大内存多核服务端。
标签：JVM,垃圾回收,G1
来源：付费笔记

## JV-006
题干：说一下垃圾回收器 CMS 和 G1 的区别
要点：设计上 CMS 是改良者，以牺牲 CPU 和吞吐换取最短停顿；G1 是平衡者，追求可控停顿下尽量高吞吐。堆布局上 CMS 用物理连续的经典分代（Eden、Survivor、Old），主要做老年代并发收集；G1 将堆划分为大小相等的 Region，分代由 Region 动态扮演（含 Humongous 区），化整为零是可控停顿的基础。回收上 CMS 走标记-清除，有碎片且并发期空间不足会退化 Serial Old Full GC；G1 用复制方式按停顿目标筛选回收价值最高的 Region，避免碎片、停顿可预测。CMS 于 Java 9 废弃、14 移除，G1 是 JDK 9 起的默认主力。
标签：JVM,垃圾回收
来源：付费笔记

## JU-001
题干：说一下 JUC 里有哪些类？
要点：分两类。锁与同步器：ReentrantLock（可重入，支持公平/非公平、可中断、超时尝试）、ReentrantReadWriteLock（读读不互斥）、Semaphore、CountDownLatch、CyclicBarrier 等；线程安全集合：ConcurrentHashMap、CopyOnWriteArrayList/Set（读多写少）、ConcurrentLinkedQueue、LinkedBlockingQueue 等，以分段锁或 CAS 替代 Collections.synchronizedList，并发性能更高。

## JU-003
题干：说一下线程的创建方式
要点：四种：继承 Thread 重写 run() 后调 start() 启动，受 Java 单继承限制；实现 Runnable 交给 Thread 构造，任务与线程分离更灵活；实现 Callable，call() 有返回值、可抛异常，配合 FutureTask 再交 Thread 启动；JDK 1.5 后通过线程池（Executors 或 ThreadPoolExecutor）创建，统一管理线程资源，生产环境最推荐。

## JU-005
题干：阻塞队列有哪些？拒绝策略有哪些？
要点：阻塞队列：ArrayBlockingQueue（数组、有界）、LinkedBlockingQueue（链表、可无界）、PriorityBlockingQueue（按优先级出队）、DelayQueue（延时任务）、SynchronousQueue（不存元素、仅传递）。拒绝策略是线程池满载后的处理：默认 AbortPolicy 直接抛异常；CallerRunsPolicy 由提交线程自己执行、可平滑流量；另有直接丢弃和丢弃队列最老任务，也可按业务自定义。
标签：JUC,线程池

## JU-006
题干：说一下 Lock 接口及实现类的使用
要点：Lock 是并发包的锁接口，提供显式加锁/解锁。典型实现 ReentrantLock：lock() 获取、finally 中 unlock() 释放，不手动释放易死锁。相比 synchronized 的优势：tryLock() 非阻塞尝试、lockInterruptibly() 可中断、可指定公平锁、Condition 支持多条件队列。其他实现：ReentrantReadWriteLock 读写分离适合读多写少；StampedLock（Java 8）提供乐观读。简单同步用 synchronized，需灵活性时用 Lock。
标签：JUC,锁
来源：付费笔记

## JU-009
题干：说一下 ReentrantLock 的底层原理
要点：基于 AQS：维护 volatile state（0 未占用、大于 0 被占用，重入累加）与 CLH 双向队列（存放等待线程）。加锁：lock() 先 CAS 将 state 从 0 改 1，成功即独占；失败时若持有者是当前线程则 state 加 1（可重入），否则封装成节点入队挂起。解锁：unlock() 将 state 减 1，减到 0 释放并唤醒下一个等待线程。非公平锁直接抢锁吞吐量高；公平锁排队保序性能稍低。可中断、超时、条件变量均基于 AQS 方法实现。
标签：JUC,锁
来源：付费笔记

## JU-012
题干：说说 synchronized 的用法及原理
要点：用法三种：修饰实例方法，锁当前对象实例；修饰静态方法，锁类的 Class 对象；修饰代码块，可指定锁对象、最灵活。进入时获取锁、退出时释放，保证同一时刻仅一个线程执行被保护代码。原理：底层依赖 JVM 层的 Monitor 机制与对象头中的 Mark Word，实现经历过优化。
标签：JUC,锁,synchronized
来源：付费笔记

## JU-013
题干：讲一下 Java 里的 CAS
要点：CAS 即 Compare-And-Swap 比较并交换，是一条 CPU 原子指令：值等于预期 A 才改为 B，否则不修改。优点是避免重量级互斥锁，减少上下文切换与阻塞开销。缺点：ABA 问题（A 变 B 又变回 A 察觉不到，需版本号解决）；竞争激烈时自旋重试空耗 CPU；只能保证单个共享变量的原子操作，多变量需加锁。属乐观锁思路，是 ConcurrentHashMap 等高性能工具的基石。
标签：JUC,原子操作
来源：付费笔记

## JU-014
题干：说说你对 AQS 的理解
要点：AQS 是并发包核心同步器框架，ReentrantLock、CountDownLatch 底层都基于它。内部维护 state（表示共享资源状态，如锁重入次数）和一个 FIFO 队列（排队等待的线程），提供独占、共享两种模式。用法是继承 AQS 并实现 tryAcquire/tryRelease 等自定义资源获取与释放逻辑，排队、阻塞、唤醒由框架封装。精华在于抽离同步器通用逻辑，如 ReentrantLock 的公平/非公平就是对 tryAcquire 的不同重写。
标签：JUC,AQS
来源：付费笔记

## JU-015
题干：说说 wait() 和 sleep() 的区别
要点：来源：wait() 是 Object 的方法，sleep() 是 Thread 的静态方法。场景：wait() 用于线程间通信，须在 synchronized 中配合 notify()/notifyAll()；sleep() 单纯暂停执行，随处可用。锁：wait() 会释放已持有的锁，sleep() 不释放。唤醒：wait() 可被 notify() 唤醒或超时自动醒；sleep() 只能等时间到或被 interrupt() 中断。
标签：JUC,线程基础
来源：付费笔记

## JU-016
题干：如何合理配置线程池参数？
要点：分三步：先掌握核心参数 corePoolSize、maxPoolSize、workQueue、keepAliveTime、RejectedExecutionHandler；再按任务类型定策略——CPU 密集型线程数设 CPU 核数+1 避免上下文切换，IO 密集型设 CPU 核数*2 或更高，控并发用有界队列、允许堆积可用无界但注意内存风险，拒绝策略按业务容忍度选；最后结合压测与监控（线程活跃度、队列堆积）调整，支持动态参数配置并给线程池命名。
标签：JUC,线程池
来源：付费笔记

## JU-018
题干：说一下 CountDownLatch、CyclicBarrier、Semaphore 的原理与使用场景
要点：CountDownLatch 倒计时锁：初始化 N，子任务完成调 countDown() 递减，主线程 await() 阻塞到归零，核心是"一等多"，适合服务启动等组件初始化完成、并行计算汇总。CyclicBarrier 循环栅栏：N 个线程各自 await()，到齐后同时释放，且可重置复用，核心是"互相等"，适合多阶段迭代计算。Semaphore 信号量：acquire()/release() 管理许可数，控制并发线程数做限流，如连接池设 10 个许可。
标签：JUC,同步工具
来源：付费笔记

## JU-019
题干：说一下常见的线程池类型及问题
要点：FixedThreadPool：核心=最大线程数、无界队列，任务堆积可能撑爆内存；CachedThreadPool：核心 0、最大 Integer.MAX_VALUE、SynchronousQueue、空闲 60 秒回收，易过量创建线程打满 CPU/内存；SingleThreadExecutor：单线程+无界队列，同样有堆积风险；ScheduledThreadPool：用 DelayedWorkQueue 执行定时任务，周期任务抛异常后不再继续执行；WorkStealingPool（Java 8）：基于 ForkJoinPool 工作窃取，适合 CPU 密集、任务独立。推荐直接用 ThreadPoolExecutor 构造。
标签：JUC,线程池
来源：付费笔记

## MY-003
题干：什么是数据库事务？
要点：一组要么全部成功、要么全部失败的数据库操作序列。四大特性：原子性，多个操作是不可分割的整体，任一失败则已执行操作全部撤销、回到初始状态；一致性，事务完成后数据状态与业务规则一致，如转账前后双方总额不变；隔离性，并发事务间操作互不干扰；持久性，提交后操作必须持久化到数据库。

## MY-004
题干：讲一讲 MVCC 实现原理
要点：多版本并发控制，读旧版本、写新版本，读写互不阻塞，用于读已提交与可重复读级别。三大机制：版本链，每行隐含 DB_TRX_ID、DB_ROLL_PTR 字段，修改产生新版本串成链；ReadView，含活跃事务 ID 列表、最小活跃事务 ID、下一分配事务 ID，据此判定版本可见性；undo log 存历史版本。读已提交每次查询新建 ReadView，可重复读仅首次生成后复用；代价是旧版本空间开销与 undo log 膨胀。

## MY-005
题干：redo log、undo log、binlog 各自作用？

## MY-006

## MY-007
题干：说说悲观锁和乐观锁
要点：悲观锁假设冲突必然发生，取数据前先加锁，用完释放，适合写多读少的高冲突场景，如秒杀库存扣减用行锁防超卖；乐观锁假设冲突少见，读取不加锁，更新时校验版本号或时间戳是否被改动，版本不符则更新失败，靠重试或报错处理，适合读多写少场景如文章点赞数更新，不阻塞读。选择取决于业务并发冲突的严重程度。

## MY-008
题干：说一下索引的分类
要点：按数据结构：B+ 树索引最主流，适合范围查询与排序；哈希索引等值查询近 O(1)，不支持范围；全文索引面向大文本关键词检索；空间索引用于地理数据。按物理存储：聚集索引叶子存整行、一表仅一个，InnoDB 主键即聚集索引；非聚集索引叶子只存主键，查整行需回表。按逻辑：主键、唯一（允许多个 NULL）、普通、联合（最左前缀匹配）、覆盖索引。

## MY-009
题干：覆盖索引、回表查询、索引下推的概念及作用
要点：回表查询：二级索引只存索引列与主键，查询字段未全部包含在索引中时，需先查得主键再回聚簇索引取整行；覆盖索引：索引涵盖查询所需全部字段，直接在索引层返回结果，彻底避免回表；索引下推：复合索引下将 WHERE 中属于索引列的条件在索引遍历时提前过滤，如 (name,age) 索引查询 name LIKE '张%' AND age=20 时先按 age 过滤，减少回表次数。三者共同目标是减少磁盘 IO。

## MY-010
题干：说一下联合索引的最左匹配原则，如何合理设计联合索引？
要点：最左匹配：联合索引按字段顺序排列，查询条件必须从最左列开始才能命中，如 (A,B,C) 支持 A、A+B、A+B+C 查询，单独 B 或 C 不生效，如同电话簿先按姓再按名排序。设计要点：高频 WHERE 字段与区分度高的列放左边；利用覆盖索引免回表；避免冗余，已有 (A,B) 再建 (A) 冗余，(B) 需单独建；范围查询列放最后，避免其后字段无法用索引。

## MY-015
题干：为什么 MySQL 用 B+ 树，MongoDB 用 B 树？

## RD-004
题干：说说 Redis 的过期删除策略
要点：惰性删除加定期删除的组合。定期删除：默认每隔约 100ms 随机抽取一批设过期时间的 Key 检查并删除，随机抽取避免全量遍历的 CPU 压力，但会有漏删；惰性删除：访问 Key 时先检查是否过期，过期即删并返回 nil，兜底清理漏网之鱼。两者都未触及时由内存淘汰机制在内存达上限时最后兜底。不用定时删除是因海量 Key 同时过期会创建大量定时器，CPU 与内存消耗大。
标签：Redis,过期删除

## RD-005
题干：说说 Redis 的内存淘汰策略
要点：内存满时按 maxmemory-policy 淘汰。两类范围：volatile 前缀只针对设过期时间的键，allkeys 前缀针对全部键；算法有 random、LRU、LFU、TTL。volatile-lru 从过期键中淘汰最近最少使用的；allkeys-lru 全量按 LRU 淘汰；volatile-ttl 优先淘汰剩余存活时间最短的；volatile-lfu 与 allkeys-lfu 按访问频率淘汰；noeviction 为默认策略，内存满不淘汰、直接拒绝写入并报错。
标签：Redis,内存淘汰
来源：付费笔记

## RD-008

## MQ-001
题干：什么是 MQ 及应用场景？
要点：本质是应用间异步通信、解耦的中间件。核心特性三点：解耦（收发双方只认 MQ）、异步（发送即返回，提升响应速度）、削峰填谷（瞬间十万请求先存储，系统按一万的处理能力慢慢消费）。场景：下单后扣库存、发短信、发优惠券等非核心流程异步执行；日志数据同步收集；秒杀抢购流量排队；新老系统解耦订阅；延迟处理如订单 30 分钟未支付自动取消，延迟消息比定时任务轮询数据库更优雅。
标签：消息队列,MQ选型,应用场景
来源：付费笔记

## MQ-002
题干：说一下常见的 MQ 产品的对比
要点：Kafka 超高吞吐（单机百万级 QPS），适合日志、大数据，但配置多、延迟毫秒到秒级，仅保证分区内有序，消费语义为 at least once，需业务做幂等；RocketMQ 阿里开源、金融级可靠，支持事务消息、延时消息、消息重试、死信队列，适合电商交易、订单、金融；RabbitMQ 基于 AMQP 协议，路由灵活、ACK 机制完善，吞吐万到十万级、延迟最低（微秒级），适合企业级应用和复杂路由场景。选型：大数据日志用 Kafka，事务与顺序消息用 RocketMQ，灵活路由用 RabbitMQ。
标签：消息队列,产品对比,选型
来源：付费笔记

## MQ-003
题干：说一下消息的可靠性投递
要点：指消息从发送到被成功消费全程不丢失、不重复。实现手段：生产者确认（MQ 返回 ACK，未收到则重发）；消息持久化（落盘保存，MQ 重启不丢）；消费者手动 ACK（处理完成才删除，失败重新投递）；事务消息（RocketMQ 先发半消息，本地事务成功才确认投递，失败回滚）；消息去重（消费端记录消息 ID 做幂等）。实践中常组合生产者确认、持久化、手动 ACK、消费端幂等；可靠性与性能需权衡。
标签：消息队列,可靠性,消息投递
来源：付费笔记

## MQ-004
题干：说一下消息的幂等性问题
要点：成因是 MQ 为保证不丢，网络抖动、超时时会重试，导致同一条消息被多次投递。核心思路不是禁止重复，而是让消费操作幂等。方案：数据库唯一约束（如支付流水号建唯一索引，重复插入报错捕获后忽略）；状态机（处理前检查订单状态，已流转到更后状态则直接跳过）；去重表（先插入消息 ID、插入成功才执行业务，依赖唯一索引）；Redis 去重（消息 ID 设过期时间，高并发性能好，需防 Redis 重启或主从切换丢数据）；版本号（消息携带单调递增版本，仅处理大于已处理最大版本的消息）。
标签：消息队列,幂等性
来源：付费笔记

## MQ-005
题干：说一下消息的积压问题
要点：生产速度远超消费速度导致消息在队列堆积。成因：消费逻辑 Bug 不断重试或卡死；消费性能不足（数据库压力大、外部接口慢）；突发流量如大促；消费模型设计不合理（快慢消息混在一个队列、消费者数量不足。应急：扩容消费实例、优化消费逻辑与批处理；严重时写临时消费程序不做业务，快速读出转存数据库或临时队列，高峰后慢慢处理；可按业务重要性丢弃部分非核心消息。治本：复盘代码瓶颈、分区数不足限制并发、监控告警缺位，按优先级划分队列，完善队列深度与生产消费速度差值的阈值告警。
标签：消息队列,消息积压
来源：付费笔记

## MQ-006
题干：说一下消息的顺序性问题
要点：指生产者按序发送的消息，消费时能否保持同样顺序。乱序原因：多分区并行消费且速度不一致；生产者发送失败重试导致乱序到达 Broker；消费者失败重试时跳过阻塞消息先处理后续。应对：局部顺序最实用——同一关键标识（订单 ID、用户 ID）的消息哈希到同一分区，不同标识间可并行；单分区全局顺序——Topic 仅一个分区、一个消费者，吞吐极低，不推荐；业务层——消费端检查前置消息是否处理完，未完成则暂存等待，实现复杂。实践中不追求全局顺序，以分区键设计保证关键业务维度的局部顺序。
标签：消息队列,顺序性
来源：付费笔记

## MQ-007
题干：说一下 MQ 的分布式事务解决方案
要点：核心是利用可靠投递和最终一致性替代强一致性事务。本地消息表：消息与业务操作在同一个本地事务落库，定时任务扫描消息表发送 MQ 并更新状态、失败重试，不依赖 MQ 的事务能力，但多一张表且业务与消息耦合；RocketMQ 事务消息：先发对消费者不可见的半消息，MQ 回调生产者执行本地事务，成功则提交（消费者可见）、失败则回滚，生产者宕机未确认时 MQ 主动回查事务状态；最大努力通知：发送失败按策略重试几次，不保证 100% 一致，需配合对账兜底。
标签：消息队列,分布式事务
来源：付费笔记

## MQ-008
题干：说一下 RocketMQ 核心的部件和组件
要点：四大核心组件：NameServer 是轻量级路由中心，维护集群 Broker 与 Topic 路由信息，Producer、Consumer 收发消息前需先查询路由；Broker 是核心存储组件，消息发送、存储、拉取都经过它，集群部署保证高可用，分 Master（负责写）与 Slave（负责读、备份）；Producer 从 NameServer 获取路由，经负载均衡发送到合适 Broker；Consumer 支持 Push 与 Pull 两种模式，本质均为长轮询拉取，支持集群消费（组内一个消息仅一个消费者处理）与广播消费（组内每个都处理）。
标签：消息队列,RocketMQ,架构

## NET-001
题干：说一下 TCP 与 UDP 的区别
要点：TCP 面向连接，需三次握手、四次挥手，维护序列号与窗口等连接状态，开销大；UDP 无连接、轻量。TCP 面向字节流，有确认重传、流量控制、拥塞控制，保证不丢不乱序；UDP 面向数据报，保留消息边界，快但不保证送达。TCP 用于 HTTP、FTP、邮件等重准确性场景；UDP 用于直播、语音、游戏、DNS 等低延迟场景。
标签：网络,TCP,UDP
来源：付费笔记

## NET-003
题干：说一下 TCP 的可靠性保障机制
要点：核心机制：序列号与确认应答，每个报文标序列号，接收方回 ACK，超时未收到即视为丢包；超时重传，超时时间根据网络状况动态计算；校验和，校验失败直接丢弃并触发重传；流量控制，基于滑动窗口，接收方通过 ACK 通告剩余缓冲区大小；拥塞控制，含慢启动、拥塞避免、快速重传、快速恢复；接收方按序列号重排乱序报文。共同保证数据不丢、不重、按序到达。
标签：网络,TCP,可靠性
来源：付费笔记

## NET-004
题干：说一下 TCP 的滑动窗口协议
要点：TCP 滑动窗口允许发送方在窗口范围内连续发送多个报文，无需一发一等确认，实现流水线传输。作用一是流量控制：接收方通过窗口大小通告剩余缓冲区，发送方据此调整速率，窗口随接收能力动态变化；作用二是提高传输效率，充分利用带宽。收到确认后窗口向前滑动即可继续发送；丢包时配合快速重传，并与慢启动、拥塞避免协同防止网络拥塞。
标签：网络,TCP,滑动窗口
来源：付费笔记

## NET-005
题干：说一下 TCP 的拥塞控制算法
要点：围绕拥塞窗口调节发送速率。慢启动：窗口每收到一个 ACK 翻倍，指数增长，超过阈值转入拥塞避免；拥塞避免：改为线性增长，每轮加 1。超时丢包时阈值设为当前窗口一半、窗口重置为 1 重新慢启动；收到 3 个重复 ACK 则快速重传、窗口减半进入快速恢复，新数据 ACK 后回到拥塞避免。流量控制防接收方过载，拥塞控制防网络过载，发送窗口取两者较小值。
标签：网络,TCP,拥塞控制
来源：付费笔记

## NET-007

要点：无状态：服务器默认不记忆先前请求，简单易扩展，但登录态需借助 Cookie、Session、Token；请求-响应模型且单向，服务器不能主动推送，需 WebSocket 或轮询；明文传输不安全，靠 HTTPS 的 TLS/SSL 加密保障；灵活，通过 Content-Type 支持任意类型数据；HTTP/1.1 起默认持久连接，一个 TCP 连接可处理多个请求；通过方法、状态码、请求头便于扩展。

## NET-010
题干：说一下 HTTP 1.0、1.1、2.0、3.0 的区别
要点：1.0 为短连接，每次请求都重建 TCP 连接。1.1 默认持久连接复用 TCP，支持管道化、Host 头、分块传输，但响应须按序返回仍有队头阻塞。2.0 核心是二进制分帧，单连接多路复用解决 HTTP 层队头阻塞，另有 HPACK 头部压缩、服务器推送，但 TCP 丢包会阻塞所有流。3.0 改用基于 UDP 的 QUIC：流相互独立、握手 1-RTT 甚至 0-RTT、支持连接迁移。

## NET-012
题干：说一下 HTTP 与 HTTPS 的区别
要点：安全性：HTTP 明文传输；HTTPS 在 HTTP 与 TCP 间加 SSL/TLS 层，提供内容加密、身份认证、完整性保护。端口：HTTP 用 80，HTTPS 用 443。协议：HTTP 直接跑在 TCP 上；HTTPS 需先完成 TLS 握手，且必须持有 CA 颁发的证书。影响：HTTPS 握手与加解密略有开销、证书有成本，现已可忽略；搜索排名更高、浏览器把 HTTP 标为不安全，登录支付必须用 HTTPS。

## NET-014
题干：说一下什么是 Cookie、Session、Token？
要点：三者均为解决 HTTP 无状态问题。Cookie：经响应头下发、存客户端，请求自动携带，省服务器资源但易被窃取篡改且有大小限制。Session：数据存服务器端，客户端仅持 Session ID（通常经 Cookie 传递），更安全但占服务器资源。Token（如 JWT）：自包含凭证，含用户信息与有效期，服务端验签即可、无需存会话，适合分布式，缺点是过期前无法主动作废。

## NET-015
题干：HTTP3 性能更好，为什么内网微服务依然多用 HTTP2？HTTP2 内网优势是什么？
要点：HTTP/3 优势针对公网：公网丢包率约 1%、RTT 一两百毫秒；内网丢包率低于 0.001%、握手仅 0.3 毫秒，其收益在内网几乎不存在。内网多用 HTTP/2 因生态成熟（gRPC、Spring Cloud、Nginx、Envoy、Istio）；HTTP/3 基于 UDP，老旧交换机与防火墙支持差、高 QPS 下不如 TCP 高效；HTTP/2 帧机制还天然支持 gRPC 双向流，迁移成本高。

## OS-001
题干：说一下进程与线程的区别
要点：进程是资源分配的基本单位，拥有独立内存空间与文件句柄；线程是 CPU 调度的基本单位，共享进程的代码、堆与文件，仅私有栈和寄存器。进程创建、切换、销毁开销大，通信需管道、消息队列等 IPC；线程开销小，直接读写共享内存即可。进程间相互隔离，单个崩溃不影响其他进程；线程缺乏隔离，一个线程崩溃会拖垮整个进程。频繁通信用多线程，强隔离用多进程。
标签：操作系统,进程,线程
来源：付费笔记

## OS-002
题干：说一下进程的状态及转换
要点：核心三态：就绪（仅缺 CPU）、运行（正占用 CPU 执行）、阻塞（等待 I/O 等外部事件，有 CPU 也无法运行）。转换：被调度选中则就绪到运行；时间片耗尽或被高优先级抢占则运行到就绪；等待事件如发起 I/O 则运行到阻塞；事件完成如 I/O 结束则阻塞回就绪。另有创建态与终止态；内存不足时进程可换出到磁盘，形成就绪挂起、阻塞挂起。
标签：操作系统,进程,进程状态
来源：付费笔记

## OS-003
题干：说一下进程调度算法
要点：先来先服务：简单公平，长任务会拉长平均等待时间。最短作业优先：平均等待最优，但时长难预知，长任务可能饥饿。时间片轮转：固定时间片（如 10ms）轮流执行，公平、适合分时系统，片太小切换开销大、太大响应慢。优先级调度：可静态或动态调整，配合老化防饥饿。多级队列：不同队列用不同策略。现代系统多用混合策略。
标签：操作系统,进程调度
来源：付费笔记

## OS-004
题干：说一下进程间通信的方式
要点：常见方式：管道、消息队列、共享内存、信号量、信号、Socket。匿名管道（如 Shell 的竖线）仅限父子进程、单向通信；消息队列可解耦发送与接收；共享内存速度最快，多进程直接读写同一块内存，需配信号量同步；Socket 既可本地也可跨网络。选型：数据库、缓存等高性能场景用共享内存，简单传数据用管道，跨机器用 Socket，控制资源竞争用信号量。
标签：操作系统,进程间通信
来源：付费笔记

## OS-005
题干：说一下死锁的产生条件、预防、避免、检测与解除
要点：死锁指多个进程竞争资源、互相等待而无法推进。产生需同时满足四条件：互斥、持有并等待、不可抢占、循环等待。预防靠破坏其一：一次性申请全部资源、申请不到即释放已有资源、资源按编号顺序申请。避免用银行家算法：进程预先声明最大需求，系统动态判断分配后是否安全。检测靠定期检查资源分配图有无循环等待；解除靠终止死锁进程或剥夺资源。
标签：操作系统,死锁

## OS-006
题干：说一下虚拟内存的概念、作用及实现原理
要点：概念：让每个进程拥有看似私有连续的大地址空间，实际数据分散在物理内存与磁盘。作用：进程隔离与安全、物理页可多进程共享、简化编程。原理是按需加载：MMU 查页表把虚拟地址翻译为物理地址；访问不在内存的页触发缺页中断，由操作系统从磁盘调入并更新页表；内存不足时用 LRU 等置换算法换出。访问量远超物理内存会频繁换页引发抖动。
标签：操作系统,虚拟内存
来源：付费笔记

## OS-007
题干：说一下页面置换算法
要点：目标是内存不足时选出换出的页面，尽量减少缺页中断。OPT 置换未来最久不用的页，无法实现，仅作评价基准。FIFO 先进先出，实现简单，但有 Belady 异常（页框增多缺页反增）。LRU 换出最近最久未使用的页，基于局部性原理，性能接近 OPT，需记录时间戳、开销大。Clock 是 LRU 近似：环形链表加使用位，指针扫描，为 1 清零跳过、为 0 换出，成本低。LRU 可用哈希表加双向链表实现 O(1)。
标签：操作系统,页面置换
来源：付费笔记

## OS-008
题干：说一下分页存储与分段存储的区别，段页式存储的原理
要点：两者均为解决内存非连续分配。分页是物理单位：页框与页面大小固定，消除外部碎片、利用率高，仅少量内部碎片。分段是逻辑单位：按代码段、数据段划分，长度不固定，便于共享与保护，无内部碎片但有外部碎片。段页式先分段、段内再分页，地址由段号、段内页号、页内偏移组成，查段表定位页表、再查页表得页框号，兼顾逻辑清晰与空间利用率。
标签：操作系统,内存管理,分页分段
来源：付费笔记
